# Этап 15. Бэкенд на бесплатном Cloudflare, роли и регистрация по приглашению

## 🔹 Что делаем и зачем

До сих пор календарь работал так: Java-сервер (Spring Boot) + PostgreSQL + Redis + MinIO на арендованном сервере. Это стоит денег.

На этом этапе:

1. **Бэкенд переписан на TypeScript** и работает на **Cloudflare Workers** бесплатно. Сервер арендовать не нужно.
2. **Сайт остался тем же**: вход по email и паролю, как раньше.
3. **Появились роли.** Есть обычные пользователи (**USER**) и супер-пользователь, администратор (**ADMIN**).
4. **Регистрация по приглашению.** Сам по себе зарегистрироваться нельзя. Администратор на странице «Доступ» добавляет email, и только после этого человек с этим email может создать аккаунт.

Аналогия 🏠: раньше у тебя был свой магазин в арендованном помещении (сервер). Теперь ты открываешь отдел внутри большого торгового центра (Cloudflare): охрана, электричество и вывеска уже есть, а платить начинаешь, только если покупателей станет очень много. А на входе в отдел стоит охранник со списком гостей.

Java-код никуда не делся: он лежит в папке `backend/` для истории. Новый бэкенд в папке `worker/`.

## 🔹 Новые слова

| Термин | Простыми словами |
|---|---|
| **Cloudflare Workers** | код, который Cloudflare запускает на своих серверах по всему миру. Пишется на JavaScript/TypeScript |
| **D1** | база данных Cloudflare. Внутри это **SQLite**: похожа на PostgreSQL, но проще |
| **R2** | хранилище файлов Cloudflare. Как MinIO на прошлых этапах |
| **wrangler** | программа командной строки для Cloudflare: запустить у себя, выложить, создать базу |
| **Binding** (привязка) | «ручка», через которую код достаёт базу или хранилище: `env.DB`, `env.IMAGES` |
| **Hono** | маленькая библиотека для адресов API. Как `@RestController` и `@GetMapping` в Spring |
| **Middleware** («охранник») | код, который выполняется до обработчика и решает, пускать ли запрос дальше |
| **Роль** (role) | что человеку разрешено: `USER` — обычный пользователь, `ADMIN` — администратор |
| **Allowlist** (белый список) | список email, которым разрешено регистрироваться. Таблица `allowed_emails` |
| **PBKDF2** | способ превратить пароль в хеш так, чтобы подбирать его было очень долго. Вместо BCrypt из Java-версии |
| **Origin** | заголовок, в котором браузер пишет, с какого сайта отправлен запрос |
| **Miniflare** | «Cloudflare на твоём компьютере»: на нём запускаются тесты |

## 🔹 Как всё устроено теперь

```
Браузер  ──▶  https://advent-calendar.<вы>.workers.dev
                         │
           ┌─────────────┴─────────────┐
     /api/*                       всё остальное
           │                             │
  worker/src (наш код)        frontend/dist (React)
   │        │                  отдаёт Cloudflare сам
env.DB    env.IMAGES
 (D1)       (R2)
```

Один адрес, один Worker. Сайт и API живут вместе, поэтому CORS не нужен, как и раньше с nginx.

### Что было → что стало

| Было (Java) | Стало (Cloudflare) |
|---|---|
| Spring Boot, контроллеры | `worker/src/routes/*.ts` на Hono |
| PostgreSQL + Flyway (`V1…V8`) | D1 + одна миграция `worker/migrations/0001_init.sql` |
| MinIO | R2 |
| Redis (сессии, лимит попыток входа) | таблицы `sessions` и `login_failures` в D1 |
| BCrypt | PBKDF2 (`worker/src/auth/password.ts`) |
| CSRF-токен | проверка заголовка `Origin` + cookie `SameSite=Lax` |
| сервер уменьшал картинки (ImageProcessor) | уменьшает браузер (`frontend/src/lib/resizeImage.ts`) |
| `GlobalExceptionHandler` | `worker/src/errors.ts`, тот же формат ответа `{ status, detail, errors }` |
| VPS + Caddy + домен (этап 14) | Cloudflare даёт адрес `*.workers.dev` с HTTPS бесплатно |
| регистрироваться мог любой | только email из списка администратора |

Адреса API остались те же (`/api/wishes`, `/api/friends`, `/api/calendars/2?month=2026-10` и т. д.), поэтому почти весь фронтенд не поменялся.

## 🔹 Как работает вход

🔹 **Простыми словами**

Как в Java-версии: человек вводит email и пароль, сервер проверяет и выдаёт «пропуск» (**сессию**) в cookie. Дальше браузер сам показывает этот пропуск в каждом запросе.

🔹 **Как это работает**

1. `POST /api/auth/login` (`worker/src/routes/auth.ts`) находит человека и сверяет пароль с хешем.
2. Совпало — сервер создаёт случайный токен. Токен уходит в cookie `session`, а в таблицу `sessions` пишется только его хеш. Украли базу — токены всё равно не узнать.
3. На каждом запросе «охранник» `requireUser` (`worker/src/auth/middleware.ts`) ищет сессию по cookie. Нет сессии → 401 «Войдите в аккаунт».
4. Ошибся паролем 5 раз за 15 минут — сервер отвечает 429 и даже не проверяет пароль (защита от подбора, **brute force**).

Флаги cookie:

- `HttpOnly` — JavaScript на странице её не видит (не украсть через XSS);
- `Secure` — только по HTTPS;
- `SameSite=Lax` — браузер не прикладывает её к POST-запросам с чужих сайтов.

💡 Вместо CSRF-токена сервер проверяет заголовок `Origin`: изменять данные (POST, PUT, DELETE) можно только с нашего же адреса. Иначе 403 «Запрос с чужого сайта».

## 🔹 Роли и регистрация по приглашению

🔹 **Простыми словами**

Календарь как закрытый клуб: на входе список гостей (**allowlist**). Кого нет в списке, тот не может даже создать аккаунт. Список ведёт администратор на странице «Доступ».

🔹 **Кто администратор**

Первые администраторы записаны в настройке `ADMIN_EMAILS` (`worker/wrangler.jsonc`). Им можно регистрироваться всегда, и роль `ADMIN` они получают сами. В списке на странице «Доступ» их добавлять не нужно.

🔹 **Как это работает**

1. Администратор открывает кнопку **«Доступ»** в шапке (её видит только он) и добавляет email друга.
2. Друг регистрируется с этим email. С другим email сервер ответит 403 «Регистрация по приглашению».
3. Сервер проверяет список на **каждом** запросе. Администратор нажал «Закрыть» — у человека сразу удаляются сессии, войти он больше не может и пропадает из поиска друзей. Его желания не удаляются: добавил email снова — всё на месте.

🔹 **Пример: «охранник» для администратора**

```ts
// worker/src/routes/admin.ts
const requireAdmin = createMiddleware<App>(async (c, next) => {
    if (c.get('me').role !== 'ADMIN') throw new ApiError(403, 'Только для администратора');
    await next();
});
```

- `c.get('me')` — кто вошёл (его положил туда `requireUser`);
- не администратор → ошибка 403, обработчик даже не запускается;
- `await next()` — пропустить запрос дальше.

⚠ Кнопку «Доступ» фронтенд прячет от обычных людей, но это только удобство. Защищает сервер: спрятанную кнопку можно обойти, отправив запрос вручную.

🔹 **Адреса API администратора**

| Запрос | Что делает |
|---|---|
| `GET /api/admin/emails` | список разрешённых email и кто уже зарегистрировался |
| `POST /api/admin/emails` `{ "email": "..." }` | разрешить email |
| `DELETE /api/admin/emails/<email>` | закрыть доступ (администратора закрыть нельзя) |

## 🔹 Как защищены картинки

Картинки лежат в R2 и отдаются по адресу `/api/wishes/5/image?size=thumb`. Этот адрес тоже за «охранником» `requireUser`: браузер сам прикладывает cookie к `<img src="...">`. Сервер отдаёт картинку, только если ты владелец или день тебе открыт. Иначе 404.

Главное правило проекта сохранилось: **у закрытого дня ни название, ни картинка не попадают в ответ сервера.**

## 🔹 Что нужно установить

| Программа | Зачем |
|---|---|
| Node.js 20 или новее | уже стоит с прошлых этапов |
| Аккаунт Cloudflare (бесплатный) | https://dash.cloudflare.com/sign-up |

Java, Docker и сервер для этой версии **не нужны**.

# Часть 1. Запуск на своём компьютере

## 🔹 Шаг 1. Установить библиотеки

```powershell
cd frontend
npm ci
cd ..\worker
npm ci
```

## 🔹 Шаг 2. Локальные настройки

```powershell
copy .dev.vars.example .dev.vars
```

В `.dev.vars` написано `ADMIN_EMAILS=admin@example.com`: это администратор на твоём компьютере. Можешь вписать свой email.

## 🔹 Шаг 3. Создать таблицы в локальной базе

```powershell
npm run db:migrate:local
```

Должно появиться `0001_init.sql ✅`.

## 🔹 Шаг 4. Запустить

Два окна PowerShell:

```powershell
# окно 1: бэкенд (Worker) на http://localhost:8787
cd worker
npm run dev
```

```powershell
# окно 2: фронтенд на http://localhost:5173
cd frontend
npm run dev
```

1. Открой http://localhost:5173/register и зарегистрируйся с email администратора (`admin@example.com`).
2. В шапке появится кнопка **«Доступ»**. Добавь там, например, `anna@test.ru`.
3. В окне инкогнито зарегистрируй Анну с этим email. Можно дружить 🎉

💡 Vite передаёт запросы `/api` в Worker и подменяет заголовок `Origin` на `localhost:8787` (`frontend/vite.config.ts`). Без этого проверка «запрос с нашего сайта» не пропустила бы запросы с `localhost:5173`. На Cloudflare сайт и API по одному адресу, там подмена не нужна.

## 🔹 Шаг 5. Тесты

```powershell
cd worker
npm test          # 18 тестов: вход, роли, приглашения, закрытые дни, картинки, праздники
npm run typecheck # проверка типов TypeScript
```

Сквозной тест (администратор и два человека в настоящем браузере): запусти оба окна из шага 4, потом

```powershell
cd frontend
npx playwright test
```

# Часть 2. Выкладываем в Cloudflare

## 🔹 Шаг 6. Войти в Cloudflare из командной строки

```powershell
cd worker
npx wrangler login
```

Откроется браузер, нажми **Allow**.

## 🔹 Шаг 7. Создать базу D1

```powershell
npx wrangler d1 create advent
```

В ответе будет `"database_id": "xxxxxxxx-xxxx-..."`. Скопируй его в `worker/wrangler.jsonc` вместо `ВСТАВЬТЕ-СЮДА-ID-БАЗЫ`.

## 🔹 Шаг 8. Включить R2 и создать хранилище картинок

1. В панели Cloudflare слева: **Storage & databases → R2 Object Storage**.
2. Нажми **Enable R2** (включить).

⚠ Cloudflare может попросить привязать карту или PayPal даже для бесплатного тарифа. Деньги не списываются, пока не превышен бесплатный лимит (10 ГБ файлов в месяц). Нашим картинкам по 200 КБ до этого очень далеко.

Потом:

```powershell
npx wrangler r2 bucket create advent-wish-images
```

## 🔹 Шаг 9. Назначить себя администратором

В `worker/wrangler.jsonc` впиши свой email:

```jsonc
"ADMIN_EMAILS": "you@example.com",
```

Несколько администраторов — через запятую: `"you@example.com, friend@example.com"`.

## 🔹 Шаг 10. Выложить

```powershell
npm run deploy
```

Эта команда делает три вещи:

1. собирает фронтенд (`frontend/dist`);
2. создаёт таблицы в настоящей базе D1 (`migrations apply --remote`);
3. выкладывает Worker.

В конце будет адрес, например `https://advent-calendar.daniyar.workers.dev`. Проверь:

```
https://advent-calendar.<вы>.workers.dev/api/health   →   {"status":"ok"}
```

## 🔹 Шаг 11. Проверить

1. Открой адрес из шага 10, зарегистрируйся со своим email из `ADMIN_EMAILS`.
2. Нажми **«Доступ»** и добавь email друга.
3. Друг регистрируется на том же адресе. Найдите друг друга в «Друзьях» по имени.

# Часть 3. Полезное

## 🔹 Логи

```powershell
cd worker
npx wrangler tail
```

Показывает запросы и ошибки в реальном времени. Ошибка 500 содержит «Код ошибки: abc123», и тот же код будет в логе.

## 🔹 Посмотреть базу

```powershell
npx wrangler d1 execute advent --remote --command "SELECT id, name, email, role FROM users"
```

## 🔹 Новые изменения в коде

После изменений снова `npm run deploy`. Если поменялись таблицы, создай новый файл `migrations/0002_что-то.sql` (как `V9__...` во Flyway). Старые миграции не редактируй.

## 🔹 Бесплатные лимиты (на момент этапа)

| Что | Бесплатно |
|---|---|
| Workers | 100 000 запросов в день |
| D1 | 5 ГБ, 5 млн чтений строк в день |
| R2 | 10 ГБ, без платы за скачивание |

Для календаря с друзьями этого хватит с огромным запасом.

⚠ Хеш пароля считается 100 000 раз подряд (PBKDF2). На бесплатном тарифе у Worker 10 мс процессорного времени на запрос, и вход может иногда упираться в этот лимит. Если увидишь ошибку при входе в логах (`wrangler tail`), напиши: можно уменьшить число повторов.

| Файл | Что поменялось |
|---|---|
| `src/api/auth.ts` | у «кто я» появилась роль `role` |
| `src/api/admin.ts` | новый: список email, добавить, закрыть |
| `src/pages/AdminPage.tsx` | новая страница «Доступ» (`/admin`) |

| `src/lib/resizeImage.ts` | новый: уменьшает картинку до 1600 и 300 точек |
| `vite.config.ts` | запросы `/api` идут в Worker на порту 8787 |

## 🔹 Чего больше нет

- Свободной регистрации: только по приглашению администратора.
- Docker и сервера для новой версии. Файлы `docker-compose.yml`, `Dockerfile` и `deploy/` остались для старой Java-версии.
- Старые аккаунты из PostgreSQL не переносятся: в новой базе все регистрируются заново.

---

**Главное, что нужно запомнить:**

- Cloudflare Workers запускает только JS/TS, поэтому бэкенд переписан на TypeScript. База D1 (SQLite), файлы в R2.
- Вход как раньше: email и пароль, потом сессия в cookie. Вместо CSRF-токена сервер проверяет заголовок `Origin`.
- Роли: `USER` и `ADMIN`. Первые администраторы — из `ADMIN_EMAILS`.
- Регистрироваться можно только с email из списка администратора. Список проверяется на **каждом** запросе.
- Права всегда проверяет сервер. Спрятанная кнопка во фронтенде — только удобство, а не защита.
