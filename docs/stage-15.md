# Этап 15. Telegram Mini App на бесплатном Cloudflare

## 🔹 Что делаем и зачем

До сих пор календарь работал так: Java-сервер (Spring Boot) + PostgreSQL + Redis + MinIO на арендованном сервере. Это стоит денег, и войти можно только по email и паролю.

На этом этапе:

1. **Переносим календарь в Telegram.** Человек открывает бота, жмёт кнопку, и календарь открывается прямо внутри Telegram (**Mini App**, или **Web App**).
2. **Вход без пароля.** Telegram сам сообщает, кто открыл приложение, и подписывает эти данные. Сервер проверяет подпись.
3. **Бэкенд переписан на TypeScript** и работает на **Cloudflare Workers** бесплатно. Сервер арендовать не нужно.
4. **Бот присылает уведомления:** «вам пришла заявка в друзья», «друг просит открыть день», «вам открыли день».

Аналогия 🏠: раньше у тебя был свой магазин в арендованном помещении (сервер). Теперь ты открываешь отдел внутри большого торгового центра (Cloudflare): охрана, электричество и вывеска уже есть, а платить начинаешь, только если покупателей станет очень много.

Java-код никуда не делся: он лежит в папке `backend/` для истории. Новый бэкенд в папке `worker/`.

## 🔹 Новые слова

| Термин | Простыми словами |
|---|---|
| **Telegram Mini App** (Web App) | обычный сайт, который Telegram открывает у себя внутри, в окне поверх чата |
| **@BotFather** | официальный бот Telegram, через который создают своих ботов |
| **Токен бота** (bot token) | пароль бота: `123456:ABC-DEF...`. У кого токен, тот управляет ботом. Никому не показывать |
| **initData** | строка от Telegram: кто открыл приложение и когда, плюс подпись |
| **HMAC** | подпись данных секретным ключом. Без ключа подделать нельзя, а любая изменённая буква «ломает» подпись |
| **Cloudflare Workers** | код, который Cloudflare запускает на своих серверах по всему миру. Пишется на JavaScript/TypeScript |
| **D1** | база данных Cloudflare. Внутри это **SQLite**: похожа на PostgreSQL, но проще |
| **R2** | хранилище файлов Cloudflare. Как MinIO на прошлых этапах |
| **wrangler** | программа командной строки для Cloudflare: запустить у себя, выложить, создать базу |
| **Binding** (привязка) | «ручка», через которую код достаёт базу или хранилище: `env.DB`, `env.IMAGES` |
| **Webhook** | адрес, на который Telegram сам присылает сообщения боту. «Позвоните мне, когда что-то случится» |
| **Stateless-аутентификация** | сервер ничего не помнит о входе (нет сессии). Каждый запрос сам приносит доказательство «кто я» |
| **Signed URL** (подписанный адрес) | адрес картинки с подписью внутри. Работает только тот адрес, который выдал сервер |
| **Hono** | маленькая библиотека для адресов API. Как `@RestController` и `@GetMapping` в Spring |
| **Miniflare** | «Cloudflare на твоём компьютере»: на нём запускаются тесты |

## 🔹 Как всё устроено теперь

```
Telegram  ──кнопка «Открыть календарь»──▶  https://advent-calendar.<вы>.workers.dev
                                                  │
                                    ┌─────────────┴─────────────┐
                              /api/*                       всё остальное
                                    │                             │
                         worker/src (наш код)        frontend/dist (React)
                          │        │                  отдаёт Cloudflare сам
                     env.DB    env.IMAGES
                      (D1)       (R2)
```

Один адрес, один Worker. Сайт и API живут вместе, поэтому CORS не нужен, как и раньше с nginx.

### Что было → что стало

| Было (Java) | Стало (Cloudflare) |
|---|---|
| Spring Boot, контроллеры | `worker/src/routes/*.ts` на Hono |
| PostgreSQL + Flyway (`V1…V8`) | D1 + одна миграция `worker/migrations/0001_init.sql` |
| MinIO | R2 |
| Redis (кэш, лимит попыток входа) | не нужен: паролей нет, а D1 и так быстрая |
| email + пароль, сессия в cookie, CSRF | подпись Telegram в заголовке `Authorization: tma …` |
| сервер уменьшал картинки (ImageProcessor) | уменьшает браузер (`frontend/src/lib/resizeImage.ts`) |
| `GlobalExceptionHandler` | `worker/src/errors.ts`, тот же формат ответа `{ status, detail, errors }` |
| VPS + Caddy + домен (этап 14) | Cloudflare даёт адрес `*.workers.dev` с HTTPS бесплатно |

Адреса API остались те же (`/api/wishes`, `/api/friends`, `/api/calendars/2?month=2026-10` и т. д.), поэтому почти весь фронтенд не поменялся.

## 🔹 Как работает вход через Telegram

🔹 **Простыми словами**

Когда Telegram открывает наше приложение, он кладёт в `window.Telegram.WebApp.initData` строку:

```
user={"id":123456,"first_name":"Анна"}&auth_date=1730000000&hash=9f86d08...
```

`hash` — подпись. Её может посчитать только тот, кто знает токен бота: Telegram и наш сервер.

🔹 **Как это работает**

1. Фронтенд (`frontend/src/api/http.ts`) в каждом запросе отправляет заголовок `Authorization: tma <initData>`.
2. Сервер (`worker/src/auth/telegram.ts`) считает подпись сам и сравнивает с `hash`:
   - секретный ключ = HMAC-SHA256(ключ `"WebAppData"`, данные = токен бота);
   - подпись = HMAC-SHA256(секретный ключ, все поля кроме `hash`, по алфавиту, через перевод строки).
3. Совпало, и данным меньше суток → это правда этот человек.
4. Если человек впервые, `/api/me` отвечает 404, и фронтенд показывает страницу с двумя галочками (согласия). После них `POST /api/auth/register` создаёт аккаунт. Имя берём из Telegram, а не из запроса.

🔹 **Пример**

```ts
// worker/src/auth/telegram.ts (сокращённо)
const key = await secretKey(botToken, ['verify']);
const valid = await crypto.subtle.verify('HMAC', key, hash, encoder.encode(dataCheckString(params)));
```

- `secretKey(...)` — делает ключ из токена бота по правилу Telegram;
- `crypto.subtle.verify` — проверяет подпись. Сравнивает за одинаковое время, сколько бы букв ни совпало (защита от **timing attack**, атаки по времени);
- `dataCheckString(params)` — склеивает поля так, как требует Telegram.

💡 Почему больше нет CSRF-токена: cookie браузер добавляет к запросам сам, даже к запросам с чужих сайтов. А заголовок `Authorization` браузер сам не добавляет никогда. Значит, чужой сайт не может сделать запрос «от твоего имени».

## 🔹 Как защищены картинки

Картинку браузер грузит тегом `<img src="...">`, а такой запрос не умеет отправлять наш заголовок `Authorization`. Поэтому сервер выдаёт **подписанный адрес**:

```
/api/wishes/5/image?size=thumb&v=<имя файла>&u=<кому выдан>&exp=<до какого времени>&sig=<подпись>
```

При каждом запросе картинки сервер проверяет:

1. подпись верна (адрес выдал именно сервер, `u` и `exp` не подменены);
2. срок не прошёл;
3. картинку не заменили (`v` совпадает);
4. `u` — владелец, или день ему всё ещё открыт. Закрыли день → старый адрес сразу перестаёт работать.

Главное правило проекта сохранилось: **у закрытого дня ни название, ни картинка не попадают в ответ сервера.**

# Часть 1. Запуск на своём компьютере

## 🔹 Шаг 1. Установить библиотеки

```powershell
cd frontend
npm ci
cd ..\worker
npm ci
```

## 🔹 Шаг 2. Локальные секреты

```powershell
copy .dev.vars.example .dev.vars
```

В `.dev.vars` есть `DEV_AUTH=1`. Это разрешает входить без Telegram, **только** на твоём компьютере. В Cloudflare эту переменную не задаём никогда.

## 🔹 Шаг 3. Создать таблицы в локальной базе

```powershell
npm run db:migrate:local
```

Должно появиться `0001_init.sql ✅`.

## 🔹 Шаг 4. Запустить

Два окна PowerShell:

```powershell
# окно 1: бэкенд (Worker) на http://localhost:8787
cd worker
npm run dev
```

```powershell
# окно 2: фронтенд на http://localhost:5173
cd frontend
npm run dev
```

Открой в браузере:

```
http://localhost:5173/?as=1001:Анна
```

`?as=1001:Анна` значит «я Telegram-пользователь с id 1001 по имени Анна». Отметь две галочки, нажми «Начать». Во второй вкладке в режиме инкогнито открой `?as=1002:Борис`, и можно дружить 🎉

## 🔹 Шаг 5. Тесты

```powershell
cd worker
npm test          # 18 тестов: вход, закрытые дни, картинки, праздники, бот
npm run typecheck # проверка типов TypeScript
```

Сквозной тест (два человека в настоящем браузере): запусти оба окна из шага 4, потом

```powershell
cd frontend
npx playwright test
```

# Часть 2. Бот в Telegram

## 🔹 Шаг 6. Создать бота

1. В Telegram открой **@BotFather**.
2. Отправь `/newbot`.
3. Название, например: `Адвент-календарь желаний`.
4. Имя бота, обязательно на `bot`, например: `advent_wishes_bot`.
5. BotFather пришлёт **токен** вида `7012345678:AAH...`. Сохрани его, но никому не показывай и не клади в git.

Создай файл `frontend/.env.production.local` и впиши имя бота (без @):

```
VITE_BOT_USERNAME=advent_wishes_bot
```

Это не секрет, но в git файлы `.env.*` не попадают (так настроено в `.gitignore`). Имя нужно для кнопки «Открыть бота» у тех, кто зашёл на сайт не из Telegram.

# Часть 3. Выкладываем в Cloudflare

## 🔹 Шаг 7. Войти в Cloudflare из командной строки

```powershell
cd worker
npx wrangler login
```

Откроется браузер, нажми **Allow**.

## 🔹 Шаг 8. Создать базу D1

```powershell
npx wrangler d1 create advent
```

В ответе будет `"database_id": "xxxxxxxx-xxxx-..."`. Скопируй его в `worker/wrangler.jsonc` вместо `ВСТАВЬТЕ-СЮДА-ID-БАЗЫ`.

## 🔹 Шаг 9. Включить R2 и создать хранилище картинок

1. В панели Cloudflare слева: **Storage & databases → R2 Object Storage**.
2. Нажми **Enable R2** (включить).

⚠ Cloudflare может попросить привязать карту или PayPal даже для бесплатного тарифа. Деньги не списываются, пока не превышен бесплатный лимит (10 ГБ файлов в месяц). Нашим картинкам по 200 КБ до этого очень далеко.

Потом:

```powershell
npx wrangler r2 bucket create advent-wish-images
```

## 🔹 Шаг 10. Секреты

```powershell
npx wrangler secret put BOT_TOKEN
```

Вставь токен из шага 6 и нажми Enter.

```powershell
npx wrangler secret put WEBHOOK_SECRET
```

Придумай длинный пароль только из латинских букв, цифр, `_` и `-` (например, сгенерируй в менеджере паролей). Он нужен, чтобы сообщения «от Telegram» мог присылать только Telegram. Запомни его до шага 12.

💡 Секреты хранятся в Cloudflare зашифрованными. В `wrangler.jsonc` и в git их нет.

## 🔹 Шаг 11. Выложить

```powershell
npm run deploy
```

Эта команда делает три вещи:

1. собирает фронтенд (`frontend/dist`);
2. создаёт таблицы в настоящей базе D1 (`migrations apply --remote`);
3. выкладывает Worker.

В конце будет адрес, например `https://advent-calendar.daniyar.workers.dev`. Проверь:

```
https://advent-calendar.<вы>.workers.dev/api/health   →   {"status":"ok"}
```

## 🔹 Шаг 12. Подключить webhook бота

Открой в браузере (одной строкой, подставь свои значения):

```
https://api.telegram.org/bot<ТОКЕН>/setWebhook?url=https://advent-calendar.<вы>.workers.dev/api/telegram/webhook&secret_token=<WEBHOOK_SECRET>
```

Ответ должен быть `{"ok":true,"result":true,"description":"Webhook was set"}`.

Теперь на `/start` бот отвечает кнопкой «🎁 Открыть календарь».

## 🔹 Шаг 13. Кнопка меню у бота

Чтобы календарь открывался и кнопкой слева от поля ввода:

1. В @BotFather: `/mybots` → твой бот → **Bot Settings → Menu Button → Configure menu button**.
2. Пришли адрес `https://advent-calendar.<вы>.workers.dev`.
3. Пришли название кнопки: `Календарь`.

По желанию: `/mybots` → бот → **Bot Settings → Configure Mini App → Enable Mini App**, и тот же адрес. Тогда у бота появится кнопка «Открыть» в профиле.

## 🔹 Шаг 14. Проверить

1. Открой своего бота, нажми **Старт**, потом **Открыть календарь**.
2. Отметь галочки, добавь желание с картинкой.
3. Попроси друга сделать то же самое, найдите друг друга в «Друзьях» по имени или @нику.
4. Друг попросит доступ к дню, и бот пришлёт тебе уведомление 🔔

| Файл | Что поменялось |

## 🔹 Чего больше нет

- Входа по email и паролю. Старые аккаунты из PostgreSQL не переносятся: в Telegram каждый входит заново.
- Кнопки «Выйти»: приложение закрывается крестиком Telegram.
- Docker и сервера для новой версии. Файлы `docker-compose.yml`, `Dockerfile` и `deploy/` остались для старой Java-версии.

---

**Главное, что нужно запомнить:**

- Mini App — это обычный сайт внутри Telegram. Telegram сам говорит, кто открыл, и подписывает это токеном бота.
- Сервер проверяет подпись в **каждом** запросе. Сессий и cookie нет, поэтому не нужна защита от CSRF.
- Cloudflare Workers запускает только JS/TS, поэтому бэкенд переписан на TypeScript. База D1 (SQLite), файлы в R2.
- Картинки отдаются по подписанному адресу, и сервер при каждом запросе проверяет, открыт ли ещё день.
- Секреты (`BOT_TOKEN`, `WEBHOOK_SECRET`) задаются через `wrangler secret put` и никогда не попадают в git.
