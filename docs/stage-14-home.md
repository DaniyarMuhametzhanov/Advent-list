# Этап 14 (вариант «дома»). Бесплатно на своём компьютере через Tailscale Funnel

## 🔹 Что делаем и зачем

Для двух человек арендовать сервер не обязательно. Сайт будет работать **на твоём компьютере** в Docker, а программа **Tailscale** бесплатно даст ему постоянный адрес в интернете с HTTPS, например `https://advent.tail1234.ts.net`.

Аналогия 🚪: твой компьютер — квартира без вывески. Tailscale — почтовая служба с абонентским ящиком: люди пишут на адрес ящика, а служба по защищённому каналу приносит письма тебе домой. Свой домашний адрес (IP) и роутер открывать не нужно.

| | Сервер (основной `stage-14.md`) | Дома (этот файл) |
|---|---|---|
| Цена | ~9 000 ₸/мес + домен | бесплатно |
| Адрес | свой домен | `https://имя.tailXXXX.ts.net` |
| Работает | круглые сутки | пока включён компьютер и запущен Docker |
| Данные | на сервере в Казахстане | у тебя дома, в Казахстане |

Код приложения не меняется. Новый только один маленький файл `docker-compose.home.yml`. Всё остальное из основного `stage-14.md` (Часть 1) используется как есть: `docker-compose.prod.yml`, `.env`, `deploy/backup.sh`, `deploy/restore.sh`.

## 🔹 Новые слова

| Термин | Простыми словами |
|---|---|
| **Tailscale** | программа, которая соединяет твои устройства в частную сеть через интернет. Бесплатна для личного использования |
| **Tailnet** | твоя личная сеть в Tailscale. У неё есть имя вида `tail1234.ts.net` |
| **Funnel** («воронка») | функция Tailscale: открыть один сайт с твоего компьютера **всему интернету**. Друзьям ничего ставить не нужно, им хватает браузера |
| **Туннель** (tunnel) | защищённый «проход» от сервера Tailscale до твоего компьютера. Соединение открывает твой компьютер сам, поэтому роутер настраивать не нужно |
| **Файл-дополнение** (override) | второй docker-compose-файл, который поверх первого что-то меняет. Указывается вторым `-f` |

## 🔹 Как всё будет устроено

```
Браузер друга ──▶ https://advent.tail1234.ts.net
                     │
                     ▼
              Серверы Tailscale (Funnel)
                     │ туннель
                     ▼
   ┌──────── Твой компьютер ───────────────────────────────┐
   │ Tailscale: HTTPS-сертификат, передаёт в 127.0.0.1:8088 │
   │     ▼                                                  │
   │ Docker: frontend (nginx) → backend → postgres/redis/minio │
   └────────────────────────────────────────────────────────┘
```

Здесь Tailscale делает работу Caddy: принимает HTTPS и передаёт запросы в nginx. Он сам добавляет заголовок `X-Forwarded-Proto: https`, поэтому бэкенд понимает, что вход идёт по HTTPS, и cookie с `secure=true` работает.

## 🔹 Шаг 1. Файл-дополнение для дома

Сначала сделай Часть 1 из `stage-14.md` (шаги 1–6), если ещё не сделал. Потом создай в корне проекта `docker-compose.home.yml`:

```yaml
# Запуск на своём компьютере с Tailscale Funnel (этап 14, вариант «дома»).
# Добавляется поверх docker-compose.prod.yml:
#   docker compose -f docker-compose.prod.yml -f docker-compose.home.yml up -d --build
# HTTPS делает Tailscale, поэтому Caddy не нужен, а nginx открываем только для своего компьютера
services:
  caddy:
    profiles: ["server"]          # сервис с профилем не запускается, пока профиль не указан явно

  frontend:
    ports:
      - "127.0.0.1:8088:80"       # 127.0.0.1 — дверь только изнутри компьютера, не для соседей по Wi-Fi
```

Разбор:

* Два `-f` при запуске: Docker берёт `docker-compose.prod.yml` и **накладывает** сверху этот файл. Что здесь написано — меняется, остальное остаётся как было.
* `profiles: ["server"]` у Caddy — тот же приём, что `profiles: ["app"]` на этапе 13: сервис с профилем не запускается, пока не попросишь. Дома Caddy не нужен.
* `"127.0.0.1:8088:80"` — открыть nginx на порту 8088, но **только для самого компьютера**. Без `127.0.0.1:` к сайту мог бы зайти любой в твоей Wi-Fi-сети по обычному `http`, мимо HTTPS. Tailscale заходит изнутри компьютера, ему этого хватает.

## 🔹 Шаг 2. Файл `.env`

Создай в корне `.env` (он не попадёт в Git). Пароли сгенерируй в Git Bash командой `openssl rand -hex 24` (два раза):

```
DOMAIN=advent.tail1234.ts.net
DB_PASSWORD=первая-строка-из-openssl
STORAGE_SECRET_KEY=вторая-строка-из-openssl
```

`DOMAIN` дома Caddy не использует, но `docker-compose.prod.yml` без него не запустится (так задумано на шаге 1 основного файла). Пока впиши что угодно, а в шаге 6 поменяешь на настоящий адрес — так в `.env` будет записано, где живёт сайт.

💡 Сохрани копию `.env` в менеджере паролей.

## 🔹 Шаг 3. Запуск приложения

Останови обычный запуск для разработки (он тоже занимает порт 8088):

```powershell
docker compose --profile app down
```

Запусти «боевую» версию:

```powershell
docker compose -f docker-compose.prod.yml -f docker-compose.home.yml up -d --build
docker compose -f docker-compose.prod.yml -f docker-compose.home.yml ps
```

Должно быть пять сервисов `Up` (Caddy среди них нет — так и надо).

Проверка: открой `http://localhost:8088/api/health` → `{"status":"ok"}`.
Зарегистрироваться на `http://localhost:8088` пока **не получится** — профиль prod отправляет cookie входа только по HTTPS. Это нормально, HTTPS даст Tailscale.

💡 Анны, Бориса и Вики здесь нет, база отдельная от той, что для разработки (тома `advent_...`, а не `advent-list_...`).

## 🔹 Шаг 4. Установить Tailscale

1. Скачай Tailscale для Windows: https://tailscale.com/download/windows и установи.
2. В трее (возле часов) появится значок Tailscale. Нажми **Log in** и войди через Google, Microsoft или GitHub. Тариф выбирать не нужно: личный (Personal) бесплатный.
3. Открой https://login.tailscale.com/admin/machines — там твой компьютер в списке.

## 🔹 Шаг 5. Красивое имя (по желанию)

Адрес сайта будет `https://<имя-компьютера>.<имя-tailnet>.ts.net`.

* **Имя компьютера**: на странице Machines нажми `...` у своего компьютера → **Edit machine name** → например `advent`.
* **Имя tailnet**: страница **DNS** (https://login.tailscale.com/admin/dns) → блок **Tailnet name**. Tailscale предлагает выбрать из «забавных» вариантов (**Rename tailnet**). Сделай это **до** первого запуска Funnel: потом адрес поменяется.

## 🔹 Шаг 6. Открыть сайт в интернет

На той же странице **DNS** проверь, что включены **MagicDNS** и **HTTPS Certificates** (кнопки Enable). Потом в PowerShell:

```powershell
tailscale funnel --bg 8088
```

* `funnel` — открыть сайт всему интернету.
* `8088` — куда передавать запросы: `http://127.0.0.1:8088`, то есть наш nginx.
* `--bg` (background) — работать в фоне и **после перезагрузки** тоже. Окно можно закрыть.

Если команда напечатает ссылку вида `https://login.tailscale.com/f/funnel?...` — открой её и нажми **Enable**: так ты разрешаешь Funnel для своего tailnet. Потом повтори команду.

Команда напечатает адрес, например:

```
Available on the internet:
https://advent.tail1234.ts.net/
|-- proxy http://127.0.0.1:8088
```

Впиши этот адрес (без `https://` и `/`) в `DOMAIN` в `.env`.

⏳ Первое открытие может занять до минуты: Tailscale получает сертификат.

## 🔹 Шаг 7. Проверка руками

1. Открой адрес из шага 6 — замочек, без предупреждений.
2. Зарегистрируйся, добавь желание с картинкой.
3. Пусть друг откроет тот же адрес **у себя** (телефон с мобильным интернетом тоже подходит, Wi-Fi отключить). Ему не нужно ничего устанавливать.
4. Сценарий из макета: друзья, открытый день, закрытый день.
5. Проверь, что сайт **не** открывается в обход HTTPS: с телефона в той же Wi-Fi открой `http://<IP-компьютера>:8088` — не должно открыться.

Полезные команды:

| Команда | Что делает |
|---|---|
| `tailscale funnel status` | показать, что сейчас открыто в интернет |
| `tailscale serve reset` | закрыть сайт для интернета (приложение в Docker продолжит работать) |
| `tailscale funnel --bg 8088` | открыть снова |

## 🔹 Шаг 8. Чтобы сайт не «засыпал»

Сайт работает, только пока компьютер включён. Чтобы он не пропадал сам:

* **Сон**: Параметры Windows → Система → Питание → «Переводить в спящий режим» → **Никогда** (хотя бы при питании от сети).
* **Docker после перезагрузки**: Docker Desktop → Settings → General → **Start Docker Desktop when you sign in to your computer**. Контейнеры поднимутся сами благодаря `restart: unless-stopped`.
* **Tailscale после перезагрузки** стартует сам, Funnel с `--bg` тоже.

## 🔹 Шаг 9. Резервные копии

Скрипты из основного файла работают и дома. В Git Bash в папке проекта:

```sh
sh deploy/backup.sh
```

Чтобы копия делалась каждый вечер сама, создай задачу в **Планировщике заданий Windows** (Task Scheduler — аналог cron). В PowerShell:

```powershell
$action  = New-ScheduledTaskAction -Execute "C:\Program Files\Git\bin\sh.exe" -Argument "deploy/backup.sh" -WorkingDirectory "C:\Users\rando\Desktop\advent-list"
$trigger = New-ScheduledTaskTrigger -Daily -At 21:00
Register-ScheduledTask -TaskName "advent-backup" -Action $action -Trigger $trigger
```

* `New-ScheduledTaskAction` — **что** запускать: `sh.exe` из Git Bash со скриптом бэкапа.
* `New-ScheduledTaskTrigger -Daily -At 21:00` — **когда**: каждый день в 21:00 (компьютер в это время должен быть включён).
* `Register-ScheduledTask` — сохранить задачу под именем `advent-backup`.

Проверить сразу, не дожидаясь вечера: `Start-ScheduledTask -TaskName "advent-backup"`, через минуту загляни в папку `backups`.

⚠️ Копии лежат на том же диске. Раз в неделю копируй папку `backups` на флешку или в облако — если диск сломается, пропадёт всё вместе.

Восстановление — как в основном файле: `sh deploy/restore.sh backups/db-....sql.gz backups/images-....tar.gz`.

## 🔹 Шаг 10. Логи и обновление

Всё как в основном файле, только к командам добавляется второй `-f`. Чтобы не набирать длинно, в PowerShell можно сделать функцию на время сеанса:

```powershell
function dc { docker compose -f docker-compose.prod.yml -f docker-compose.home.yml @args }
dc ps
dc logs backend --tail 100
```

Новая версия кода (в папке проекта, ветка `master`):

```powershell
dc up -d --build
```

## 🔹 Если что-то не так

| Что видишь | Почему | Что делать |
|---|---|---|
| `required variable DOMAIN is missing` | нет `.env` или в нём нет `DOMAIN` | шаг 2 |
| `port is already allocated` на 8088 | запущена версия для разработки | `docker compose --profile app down` |
| `tailscale` не найден в PowerShell | Tailscale не установлен или PowerShell открыт до установки | установи (шаг 4) и открой новое окно PowerShell |
| `Funnel not available` / просит ссылку | Funnel или HTTPS не включены для tailnet | открой ссылку из сообщения, нажми Enable; проверь шаг 6 |
| Адрес не открывается у друга, а у тебя открывается | у тебя он может идти по частной сети Tailscale, а Funnel выключен | `tailscale funnel status` — должно быть «Available on the internet» |
| `502 Bad Gateway` | Docker не запущен или бэкенд ещё стартует | запусти Docker Desktop, подожди минуту, `dc ps` |
| Вход сразу выкидывает обратно | сайт открыт по `http://localhost:8088` | заходи по адресу `https://...ts.net` |
| Сайт пропадает ночью | компьютер уснул | шаг 8 |

## Главное, что нужно запомнить

* **Funnel** открывает сайт с твоего компьютера всему интернету с HTTPS. Роутер и белый IP не нужны.
* Tailscale здесь делает работу Caddy: HTTPS и передача запросов в nginx с заголовком `X-Forwarded-Proto: https`.
* `127.0.0.1:8088:80` — порт открыт только для самого компьютера, чтобы никто не зашёл в обход HTTPS.
* Сайт живёт, пока компьютер включён: отключи сон и включи автозапуск Docker.
