# Этап 0. Подготовка

## 🔹 Что делаем и зачем

Готовим «пустую коробку» для проекта: папки, систему учёта изменений и описание.
Код писать пока не будем. Это как перед ремонтом: сначала расставить коробки и подписать их.

## 🔹 Структура папок

- `backend/` — сервер (**бэкенд**): хранит данные и проверяет права.
- `frontend/` — то, что видит человек в браузере (**фронтенд**).
- Обе части в одном репозитории (**монорепозиторий**), так проще новичку: всё в одном месте.

Пустые папки Git не сохраняет, поэтому в них лежит пустой файл `.gitkeep` (это просто договорённость, не особый файл Git).

## 🔹 Git — что это

Git — программа, которая запоминает каждое сохранённое состояние кода (**коммит**).
Можно вернуться назад, посмотреть, что менялось. GitHub — сайт, где хранится копия (**удалённый репозиторий**).

## 🔹 .gitignore — что это

Список файлов, которые Git **не должен** сохранять:
- `node_modules/`, `target/` — то, что собирается автоматически (**артефакты сборки**). Их можно пересоздать, хранить незачем.
- `.env` — файл с паролями и ключами (**секреты**). В Git их класть нельзя никогда.
- `.idea/` — настройки редактора, у каждого свои.

## 🔹 Проверка установки

Открой новый терминал (PowerShell) и выполни по очереди:

```
git --version
java -version
node -v
npm -v
docker --version
```

Каждая команда должна напечатать номер версии. `java -version` должна показать `21`.
Если пишет «не является внутренней или внешней командой» — программа не установлена или терминал открыт до установки (закрой и открой заново).

## 🔹 Первые команды Git

```
git config --global user.name "Твоё имя"
git config --global user.email "твоя@почта"
cd wishlist-calendar
git init
git add .
git commit -m "Этап 0: структура проекта"
```

По шагам:
1. `git config` — один раз говорим Git, кто автор изменений.
2. `git init` — превращаем папку в репозиторий (появляется скрытая папка `.git`).
3. `git add .` — отмечаем все файлы для сохранения (**индекс**, staging).
4. `git commit` — делаем снимок с подписью (**коммит**).

Проверка: `git log --oneline` покажет один коммит; `git status` скажет «nothing to commit».

## Главное, что нужно запомнить

- Проект = две части: `backend/` (Java) и `frontend/` (React) в одном репозитории.
- `.gitignore` — список того, что не попадает в Git; секреты и собранные файлы всегда там.
- Коммит — сохранённый снимок кода с подписью.
- Перед работой проверь версии: Java 21, Node, Git, Docker.
